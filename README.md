# metaproject

Core Metaproject npm package. It is a development/build dependency for applications whose compiled components are served as static browser assets.

## Install in an existing application

```bash
npm install --save-dev metaproject
npx metaproject init
```

For an unpublished/local package tarball:

```bash
npm install --save-dev /path/to/metaproject-0.6.2.tgz
npx metaproject init
```

The canonical project shape is:

```text
metaproject.yaml
openapi.yaml
components/
public/components/       # generated by build
```

A default config looks like:

```yaml
version: 1
name: Example
api_root: /api
openapi: openapi.yaml
components:
  source: components
  output: public/components
canvas:
  - id: overview
    name: Overview
    items: []
```

Canvas views/layouts live inside the `canvas:` list. Do not create a `views/` folder.

## Agent workflow

`npx metaproject init` adds an `AGENTS.md` section pointing agents at the skills shipped by the installed package:

```text
skills/application-analysis/SKILL.md
skills/component-creator/SKILL.md
skills/component-authoring/SKILL.md
```

`application-analysis` inspects existing source, models or updates Operations/Entities/examples in `openapi.yaml`, then hands off to `component-creator`. `component-creator` builds the smallest useful UI using only the modeled `api.<operationId>()` methods. The skills are core-only: they do not depend on the Canvas application.

## OpenAPI example contract

Every Operation with a response body must provide a small representative success example. The default example should show normal behavior: lists should normally contain a couple of records, item responses one record, and mutation responses one representative result. Empty structured values are not accepted as the default showcase example.

Check the contract with:

```bash
npx metaproject openapi check-examples
```

`npx metaproject build` performs the same check before compiling static assets.

## Deterministic OpenAPI tools

Create/update an Entity from JSON:

```bash
npx metaproject openapi upsert-entity --input /tmp/entity.json
```

Create/update an Operation from JSON:

```bash
npx metaproject openapi upsert-operation --input /tmp/operation.json
```

Existing `x-project-id` values are preserved when updating existing resources; new resources get stable UUIDs when first created.

Import a bundled OpenAPI 3.x spec:

```bash
npx metaproject import-openapi https://example.test/openapi.yaml
```

The importer fills missing `operationId` and `x-project-id` metadata. It currently requires a bundled document (internal `$ref` is fine; external file/URL `$ref` must be bundled first). Use `--force` to intentionally replace a non-empty local spec.

## Static production build

```bash
npx metaproject build
```

This builds `public/components/` including the generated API client, runtime, component modules, registry/index, manifest and shared chunks. Output is browser-native ESM and is intended to be served directly by a PHP/web application.
