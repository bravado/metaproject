# Security policy

Metaproject Core is a development/build tool and browser runtime. Vulnerability
reports about package distribution, code generation, the CLI, dependencies, or
generated browser assets are welcome.

## Supported versions

| Version | Security fixes |
| --- | --- |
| Latest published `0.11.x` | Supported following the first public release |

The project is preparing its first public release. Unpublished development
snapshots have no separately maintained security update channel.

## Report a vulnerability privately

**Do not open a public issue or pull request containing exploit details, secrets,
or a proof of concept for an unpatched vulnerability.**

Use [GitHub's private vulnerability reporting page](https://github.com/metaproject/core/security/advisories/new)
to submit a report to the maintainers. Include:

- a clear description of the issue and potential impact;
- affected versions and the relevant execution environment;
- minimal reproduction steps or a proof of concept;
- any suggested mitigation, if known.

The reporting form is available to external researchers only after a repository
administrator enables **Private vulnerability reporting** on the public
repository. **Enabling and verifying that form is a required publication step**
tracked in [issue #22](https://github.com/metaproject/core/issues/22). If the
reporting form is unavailable, do not disclose a vulnerability in a public
issue; contact a repository maintainer privately to arrange a secure report.

Maintainers will coordinate investigation and fixes through a private
security advisory when appropriate. Please allow time for triage and
coordinated disclosure; no fixed response or remediation timeline is promised.

For non-security bugs, use the
[public issue tracker](https://github.com/metaproject/core/issues).
